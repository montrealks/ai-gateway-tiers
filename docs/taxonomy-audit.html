Is the taxonomy right?

Tier-system audit — 8 August 2026 · not "what can migrate", but "are the names true"

The previous pass (docs/integration-map.html) asked what can move onto the router and what blocks it. That takes the taxonomy as given. This pass tests the taxonomy itself, by applying one rule to every named thing across the fleet:

A tier is only a tier if its members are genuinely interchangeable — any of them answering is acceptable, and the caller does not care which won.

If a name instead pins a model because of calibration, licensing, tool dialect, output-format lock-in, or a measured behaviour nothing else reproduces, it is a route, not a tier. Calling it a tier is a latent bug: a chain will silently substitute a model that breaks the caller's assumption, return 200, and pass every test.

Verdict

The four concepts are right. The population of them is not. capability / tier / route / policy is a sound decomposition — every failure found below is expressible in it. But of 26 named things across five tables and four languages, 11 are mislabelled, the capability set is missing seven members with genuinely different failure contracts and carries one dead one, and the policy axis is implemented in exactly one of the three clients.

The deeper structural finding: nothing enforces the taxonomy. The Python client at client/aigw.py:40-47 reads only tiers, profiles and azure_api_version out of tiers.json. The capabilities, routes, policies, policy_order and policy_model blocks — the entire model under test — are read by nothing on that rail. Only llm-tiers-worker/src/index.js implements them, and per docs/architecture-2026-08-08.html defect #7 it has no production traffic. So the failure contracts are currently prose.

The most dangerous single mislabel is not gate. It is route1views' SpamScoreService. It asks for the tier dynamic/low — a genuinely rotating three-model chain resolved at the Cloudflare edge — and feeds the 0-100 number that comes back into a fixed cutoff of 70 that decides whether a user's submission is published or unlisted (SpamScoreService.php:335, CreatorController.php:546, UnlistedViewService.php:52). gate is a route wearing a tier's name but at least pins the calibrated model. This one is a calibrated threshold sitting on top of a chain that can change model with no deploy, no code change, no test failure and no log line — a dashboard edit is enough.

The determinism trap, in detail

Six helloplaydate call sites pass temperature=0 because their numbers are thresholded (face_check.py:89, likeness_gate.py:118, identity_check.py, vision_meta.py:99, outline_reviewer.py:124, list_ingest.py:151). Three models HTTP 400 on a temperature field — gpt-5.6-luna, gpt-5.6-terra, claude-sonnet-5 (probed 2026-08-08, ai_gateway.py:670-694). The three clients then do three different things:

ClientWhat it does with temperatureResult
helloplaydate ai_gateway.py:688-697Drops it per-link via _REJECTS_TEMPERATUREcorrect — honest no-op on that link, model preserved
client/aigw.py:143-144Sends it unconditionally on every Azure stepstealth swap — chat("offload", …, temperature=0) 400s on luna and lands on DeepSeek-V4-Flash. 200 returned, tests pass

That fix has not travelled to the other two clients.

The policy set

free / fast / cheap / best. Four findings.

1. It is implemented in one client out of three

client/aigw.py has no policy parameter at all — grep returns zero hits across client/. It implements profile (:207-219), a different axis with a different key. The kboodle/route1views PHP paths do not have one either. Only worker/src/index.js:257-262, :310, :404-408 reads policies, policy_order and policy_model, and it has no production traffic. The policy system is currently a design document.

2. Three of the four names collapse to one

tiers.json → _policy_implementation: "Omitting policy uses the declared chain, which IS the free default", so free ≡ default. And tiers.json → _policy: "cost is NOT a selection criterion while [the credits] last", so cheap ≡ free until ~2026-09-21. That leaves two live axes, fast and best, until the credit cliff — at which point all four become meaningful at once, with no measurement to order them by.

3. Policies silently do nothing on half the tiers — which the file itself calls the worse outcome

low and embed declare no policy_order. The Worker rejects unknown policy names (index.js:261) but accepts inapplicable ones, so {"tier":"low","policy":"best"} returns 200 having done nothing. This is precisely what _policy_implementation forbids: "a policy that quietly does nothing is worse than an error". cheap is meaningless for embed in principle, not just in implementation — a one-model capability has no cost axis, and the same is true of likeness-edit, whose policy_model lists the same model for all three policies.

4. Three axes are missing

That is a policy decision being carried by the tier — the same capability, two names, split on a cost rule.

What follows from this

  1. Make the contract executable. The taxonomy's whole value is that a mislabel becomes an error. Today capabilities is inert on the Python rail. A capability that declared vocabulary-validated-only or no-failover-without-recalibration and was enforced would have caught most of this table at call time.
  2. Rename before recalibrating. gate, transcribe and embed are already pinned correctly; they are just filed in the wrong table, where the next editor will reasonably add a link. Moving them to routes costs nothing and removes the invitation.
  3. SpamScore is the one that needs a decision, not a rename. It is calibrated against a chain, which cannot be made true by relabelling. Either pin the model or replace the fixed 70 with a per-model cutoff.
  4. Port the _REJECTS_TEMPERATURE table into client/aigw.py. It is the reference client, and it currently ships the stealth-swap bug that helloplaydate already diagnosed and fixed locally.
